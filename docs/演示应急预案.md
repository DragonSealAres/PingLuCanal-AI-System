# 演示应急预案

## 网络断开

- 提前准备本地截图或录屏。
- 后端、PC端、移动端尽量使用本机地址运行。
- 现场只演示已缓存页面时，说明真实接口已在测试报告中验证。

## 千问API不可用

- 检查 `AI_API_KEY`、额度、模型权限和网络。
- 如现场无法恢复，可临时启用 `ai.mock-enabled=true` 保证流程演示。
- 明确说明Mock仅用于现场兜底，正式测试以真实API为准。

## 高德地图加载失败

- 检查 `VITE_AMAP_KEY` 和 `VITE_AMAP_SECURITY_JS_CODE`。
- 检查高德控制台Web端Key的域名白名单是否包含当前访问地址。
- 使用隐患列表和Dashboard继续展示真实数据。

## 数据库连接失败

- 确认MySQL服务已启动。
- 确认数据库 `pinglu_ai` 存在。
- 重新执行 `docs/sql/schema.sql`。
- 检查 `MYSQL_ROOT_PASSWORD` 是否配置。

## 移动端无法打开

- 确认 `npm run dev:h5` 正在运行。
- 使用同一局域网地址访问，或改用本机浏览器模拟移动端。
- 确认 `VITE_API_BASE_URL` 指向可访问的后端地址。

## 图片识别效果不稳定

- 提前准备清晰的演示图片。
- 使用光线充足、主体明确的隐患图片。
- 如果识别结果不完全准确，可在管理员审核环节修正，体现“AI辅助、人机协同”的设计。

## 建议提前准备

- 至少10条课程演示隐患数据。
- 一组处理前后图片。
- 已导入的RAG演示知识库。
- 一段完整业务流程录屏。
- 本地 `.env.local` 或 `.env.local.ps1`，但不得展示真实密钥。
