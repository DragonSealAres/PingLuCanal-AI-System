# 系统架构

## 总体架构

```mermaid
flowchart LR
  Mobile[uni-app/H5移动端] -->|拍照上报/工单处理/RAG问答| Backend[Spring Boot 3 后端]
  Admin[Vue3 PC管理后台] -->|隐患管理/地图/Dashboard/知识库| Backend
  Backend -->|MyBatis Plus| MySQL[(MySQL 8)]
  Backend -->|多模态识别/图片复核/文本问答/Embedding| Qwen[千问API]
  Admin -->|JS API 2.0| AMap[高德地图]
  Backend --> Uploads[(本地uploads图片目录)]
```

## 模块说明

- 移动端：面向巡检员和处置人员，提供拍照上报、AI识别确认、我的上报、我的工单、处理结果提交和AI助手。
- PC管理端：面向管理员，提供隐患审核、工单派发、复核完成、航道隐患一张图、Dashboard、知识库管理和RAG问答。
- 后端：统一承载业务接口、文件上传、AI调用、RAG检索、状态流转和数据库访问。
- MySQL：存储隐患、工单、知识库文档、知识切片、问答会话和问答消息。
- 千问API：提供图片隐患识别、处置前后图片复核、文本问答和Embedding能力。
- 高德地图：在PC管理端展示隐患点位和风险等级。

## 核心业务闭环

```mermaid
sequenceDiagram
  participant I as 巡检员移动端
  participant B as Spring Boot
  participant A as 千问API
  participant P as PC管理端
  participant H as 处置人员移动端
  participant D as MySQL

  I->>B: 上传巡检图片和位置
  B->>A: 调用图片识别
  A-->>B: 返回类型、风险、描述、建议
  B->>D: 写入隐患，状态=待审核
  P->>B: 审核隐患
  B->>D: 状态=已审核
  P->>B: 创建并派发工单
  B->>D: 工单=待处理，隐患=处理中
  H->>B: 开始处理并提交处理后图片
  B->>D: 工单=待复核，隐患=待复核
  P->>B: AI智能复核
  B->>A: 调用处理前后图片复核
  A-->>B: 返回复核建议
  P->>B: 管理员最终审核
  B->>D: 工单=已完成，隐患=已完成
```

## RAG架构

```mermaid
flowchart TD
  Doc[上传/导入知识文档] --> Parse[文本解析]
  Parse --> Chunk[Chunk切分]
  Chunk --> Embed[Embedding向量化]
  Embed --> Store[(knowledge_chunk)]
  Q[用户提问] --> QEmbed[问题向量化]
  QEmbed --> Retrieve[Top-K检索]
  Store --> Retrieve
  Retrieve --> Prompt[组装Prompt和来源]
  Prompt --> LLM[千问文本模型]
  LLM --> Answer[回答+来源引用]
```
